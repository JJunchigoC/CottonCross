# 验证记录：做了哪些检查，怎么做的

本文件记录这个项目里**每一项被实际检查过的东西**，以及检查的方式。目的是让别人能复核，而不是让人相信。

运行全部检查：

```powershell
python -m unittest discover -s tests -v
```

---

## 1. 自动化测试

47 项测试，分两个文件。

### 1.1 `tests/test_core.py`（算法本身）

| 检查内容 | 怎么验证 |
|---|---|
| 蠕虫状链的弧长等于要求值 | 对 200 px 与 710 px 两个目标，数值积分后相对误差 < 2% |
| 等长先验生效 | 开启时同一画布内各纤维长度之比 < 1.02；关闭时（12 个种子）最大比值 > 1.2 |
| 完整交叉保证 | 12 个种子，每个都至少产生一个完整交叉；逐个核对交点距边界 ≥ margin 且四条分支 ≥ 56 px |
| 近似相交是难负例 | 20 个种子中至少 16 个不产生完整交叉；并说明策略名只是采样方式，标签始终来自实际几何 |
| 标签与图像对齐 | 每个交点位置上，交点热图 > 200/255 且重叠重数 ≥ 2 |
| 实例标签按曲线索引 | `instances[k]` 的每个前景像素到 `curves[k]` 的最近距离 < 2 px（这条测试正是为修复一个真实缺陷而加的：原实现按绘制顺序存储） |
| 背景归一化压低颗粒 | 构造「上半平滑、下半强颗粒、中间一条亮脊」的合成图，BGN 的颗粒比低于普通局部对比度输入 |
| 背景归一化去掉光照斜坡 | 纯线性渐变图经 BGN 后，平坦通道的绝对均值 < 0.2 |
| 背景归一化是确定性的 | 同一输入两次调用逐位相等 |
| 旋转对方向矩的变换正确 | 与解析结果比较：θ→θ−90° 时二阶矩变号、四阶矩不变 |
| 翻转对方向矩的变换正确 | 与解析结果比较：sin2θ、sin4θ 变号 |
| 渲染出的方向矩与切向一致 | 单条直线，θ=0.4，比较 cos2θ/sin2θ 的均值，容差 0.05 |
| 细化是幂等的、保持连通 | 两次细化结果逐位相等；X 形保持单连通；像素数压到一半以下 |
| crossing number 能找到 X 形 | 分支计数最大值 ≥ 4 |
| 联合匹配与端口顺序无关 | 对代价矩阵做置换，解映射回原编号后集合相同 |
| 歧义交叉被拒判 | 全相等代价矩阵下 `ambiguous=True` |
| 贪心确实会输 | 构造反例：贪心取 0.30+0.95=1.25，联合匹配取 0.68 |
| X 形解析出两条轨迹 | 1 个关节点、度数 4、2 对配对、2 条轨迹 |
| 平行线不产生交叉 | 交叉候选数 0、轨迹数 2 |
| 一对一点匹配不能靠堆点抬高召回 | 1 个真值、3 个预测 → TP=1、FP=2 |
| 碎片化扣精确率 | 整条 → TP=1；断成两截 → FP ≥ 1 |
| 所有骨干输出通道一致 | 6 个骨干都输出 18 通道、与输入同尺寸 |
| 激活后的量纲正确 | 重叠概率按通道和为 1；嵌入模长为 1 |
| OCA / DCM 可关闭 | 关闭后 `backbone.oca is None` |
| 所有损失有限可反传 | 梯度全部有限；8 个损失项都出现在返回字典里 |
| 嵌入损失方向正确 | 与实例一致的嵌入取值低于全部相同的嵌入 |
| 关掉的损失项确实消失 | 权重置 0 后对应 key 不出现 |

### 1.2 `tests/test_pipeline.py`（交付数据与流程）

| 检查内容 | 怎么验证 |
|---|---|
| 75 张原图未被改动 | 逐字节重算 SHA-256，与 manifest 比对 |
| 拍摄块不跨划分 | 每个 group 的 split 集合大小为 1 |
| 图块继承原图划分 | 逐条比对 |
| 交叉窗口合法 | 落在图像内部、扇区数 ≥ 4、划分标记与原图一致 |
| 无标注采样器只给图像 | 返回值是 uint8 灰度图；且只触及 train 图像 |
| 合成语料种子不重叠 | train/val/test/plate 的种子集合两两交集为空 |
| 每行三个文件都在 | 抽样核对 image / target / meta |
| 两项保证被记录 | provenance 中 `satisfied == of`、`equal_length` 为真、背景载体为 train only |
| 以交叉为中心的裁剪保住了交点 | 对含完整交叉的画布，裁剪后交点热图最大值 > 0.6 |
| 标定被声明为下界 | `bound == "lower"`，且 px/mm × 35 == staple_pixels |
| **模型输出不能变成真值** | 未标「完成」的页面被拒绝；外来 schema 被拒绝；真实指标文件必须声明「不是准确率」 |
| 分块推理 ≈ 单块推理 | 128px 图上，tile=128 与 tile=96/stride=48 的占据图平均差 < 0.06；嵌入保持单位模长 |
| 排行榜同时记录输赢 | `ours_is_best` 必须等于 `best == ours`；每条都带完整排名 |
| 每次训练都记录了环境 | environment.json 含 GPU 与标签策略；summary 的 `real_accuracy` 必须是 null |

## 2. 手工核对过的东西

- **背景归一化**：逐通道渲染了真实图的五联图（原图 / 平坦 / 局部 SNR / 相干性 / 基底区域），确认颗粒区被压下去、纤维仍然清晰、设备暗带被排除。
- **合成样例**：渲染了按几何策略分组的样例图，逐张确认完整交叉（蓝圈）与被裁断的交叉（橙圈）标记正确。
- **真实增强**：逐张确认每个裁剪块的圆圈落在真实可见的交叉上。
- **尺度标定**：与目视估计（纤维在图上横跨约 600–900 px）一致。
- **域差**：在网络实际看到的通道里测得前景亮度比 1.31、背景噪声比 1.09，作为已知局限写入 README，而不是隐去。
- **配色**：用移植到 Python 的六项检查器（本机无 Node）验证，相邻色对的色盲可分度 ΔE 9.1（目标 ≥ 8）、常视觉 19.6（下限 15）。三个颜色对浅背景对比度低于 3:1，因此所有柱状图直接标注数值、散点图逐点标注方法名。

## 3. 防止「自己给自己打分」的机制

这一类错误最容易在无标注项目里发生，所以做了几道硬约束：

1. **真实图像没有真值，就不报准确率。** `evaluate_real.run` 输出的字段名全是一致性统计量，且 `ground_truth` 字段明写 "not accuracy"。测试会检查这句话在不在。
2. **人工标注文件必须显式标「完成」。** `score_against_annotations` 在加载模型**之前**就校验 schema 和完成标志，未完成直接抛错——这样报错原因不会和「模型文件不存在」混淆。
3. **阈值与超参数只在验证集上选。** 交叉热图阈值（每个模型一个）由 `scripts/tools/tune_threshold.py` 在 val 上选；连接器的嵌入权重、重叠权重、拒判阈值由 `scripts/tools/tune_linker.py` 在 val 上选。两个脚本都把「测试集未参与」写进输出文件。
4. **模型选择只看合成验证集。** 训练中的 `best.pt` 由合成 val 的 Dice 决定，真实图像从不参与。
5. **排行榜如实记录输的指标。** `leaderboard.json` 里每个指标都写明第一名是谁；本文方法输掉的项会列在 `synthetic_metrics_lost` 里，并标注差距是否小于种子间波动。

## 4. 已知的、没有被验证的东西

- **真实照片的识别准确率**——没有人工真值，无法评价。
- **样本独立性**——划分按 PDF 连续页块推断，不是已知的独立样本。
- **成像模型的物理正确性**——没有做显微光学标定。
- **尺度标定的绝对正确性**——只是一个下界。
- **合成背景里是否残留弱纤维**——形态学开运算不能给出数学保证。
- **拒判阈值的概率含义**——最优与次优的成本差不是校准过的概率。
